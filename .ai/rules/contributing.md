# Contributing features

- A feature starts from an issue. Before writing code, read the issue and its comments and follow the design agreed there: where data is entered, what each view shows, which rules apply. If the issue leaves a design question open, settle it in the issue before writing code.
- Pull requests go to `tuttle-dev/tuttle`. Write the description with the sections of `.github/PULL_REQUEST_TEMPLATE.md`: `## Summary` with `Fixes #<issue>`, and `## Checklist` copied in full. Tick only the items that were actually done. Without `## Checklist`, the PR Template Check fails.
